Agent 的工作方式正在把 AI 芯片的竞争从单颗芯片推向整套系统。Agent 会规划步骤、调用工具、读取结果，再继续推理。每多走一步，模型都可能重新处理上下文、读写 KV Cache，并占用计算、内存和网络资源。因此相比 token 消耗量，当前更值得跟踪的是：==blue|**有效 Token 转化率（Effective Token Ratio）**====blue|与====blue|**单位付费价值所需的推理调用链成本**====blue|。==

Agent 会继续推高云端推理需求，也会让需求沿着 GPU、HBM、先进封装、服务器、网络、电力和液冷向上游传导。利润不会平均留在所有扩产环节。当前更有机会获得溢价的环节，要么掌握稀缺产能、良率和客户认证，要么能把芯片、软件调度和客户计费接成一套可稳定交付的系统。==blue|同时长期合同、预付款和债务融资又把未来的调用预期提前变成今天的机房和设备。最终需求一旦低于采购假设，压力会先在租赁价格这类价格信号上显现，利用率和资产回报随后才反映出来。==

端侧构成第二条需求曲线。汽车和家庭设备确实需要更低延迟、离线能力和本地数据处理，但这条曲线还要经过使用频率、设备成本和产品毛利的验证。云端已经进入大规模建设期，端侧目前更接近一项等待产品行为证明的判断。

## Agent 把任务完成变成新的成本单位

普通问答通常只有一轮输入和输出。Agent 会把一个目标拆成多步，调用外部工具，读回结果，再决定下一步。一次任务可能包含多轮模型调用，不同步骤还会使用不同大小的模型。调用次数、上下文长度、缓存命中率和失败重试共同决定最后的成本。

大模型推理通常包含 Prefill 和 Decode。Prefill 处理已经给出的输入，可以较充分地并行计算。Decode 逐个生成新 Token，需要反复读取模型权重和此前生成的 KV Cache，更容易受到内存带宽影响。上下文变长以后，KV Cache 占用还会随批量和序列长度增加。此时，计算峰值依然重要，内存容量、带宽、跨卡通信和调度效率也会直接限制吞吐。

我会用下面这笔账比较不同推理系统。

```text
每百万有效 Token 成本 = 每小时完整系统成本 ÷ 每小时有效 Token 产出 × 1,000,000
```

完整系统成本包括加速器、HBM、服务器、网络、电力、液冷、软件、托管和折旧。

每小时有效 Token 产出需要放在固定模型、平均输入输出长度、并发数、延迟和质量要求下计算。排队超时、失败重试和未达到质量要求的结果不应计入产出，输入 Token、输出 Token 和缓存命中也要分开记录。

单位任务成本下降以后，更多的工作内容和能带来潜在收入的Idea才可能进入到不同的产品和流程。同时价格进一步下降，使用量也可能增加。这种增长有一个明确前提，任务完成率和结果价值必须同时达标。单纯生成更多 Token，只会增加设备使用量，不会自动形成健康的需求。

**GPU、ASIC 与软件栈**

GPU 的利润基础来自通用性、成熟的软件生态和快速适配新模型的能力。模型架构和请求形态仍在变化时，客户可以用同一套硬件和工具处理训练、开发和多类推理任务，迁移成本也相对可控。

ASIC 可以围绕固定模型、固定精度和稳定请求形态优化成本与能效。它的经济性需要三个条件共同成立。工作负载达到足够规模，长期利用率能够覆盖芯片研发和部署投入，软件还要把客户原有的模型、算子和运维流程接进来。例如 AWS 把 Trainium 与 Neuron 软件栈、服务器、网络和云服务放在同一套产品里，Google 也用 TPU、互联和 Pathways 共同支撑大规模推理。这些说明，专用芯片的竞争单位已经扩展到整套系统。只比较单颗芯片的理论性能，很难判断它能否形成持续利润。

**HBM 与先进封装**

长上下文和并发请求会增加权重与 KV Cache 的内存占用，Decode 又需要持续搬运数据。HBM 的容量和带宽因此会影响加速器利用率。先进封装负责把计算芯片与多颗 HBM 组合起来，还要满足良率、功耗和客户认证要求。短期供给受限时，能稳定交付合格产品的供应商更容易获得溢价。

==blue|这类溢价有清楚的回落条件。新产能投放、良率改善、替代方案通过认证，或者客户开始分散采购，供给紧张带来的议价权就会减弱==（例如出现很多长鑫之类的企业）。截至 2026 年 9 月，台积电已经把全年资本开支指引上调至 600 亿至 640 亿美元，并把客户推动扩产列为主要原因。SK hynix 披露 HBM4 已在 2026 年第二季度开始量产出货，下半年继续提升产量，同时已与约十家核心客户签订长期协议。这些公司披露说明需求和扩产正在同时发生，还不足以证明当前溢价能够长期维持。

**服务器、网络、电力与液冷**

GPU 和 HBM 只有装进服务器、接入低延迟网络并获得稳定电力以后，才能形成可部署算力。Google 为 Ironwood 提供最多 9,216 颗芯片的液冷配置，整套系统功耗接近 10 MW。这个产品口径不能代表所有集群，却能说明采购边界已经延伸到芯片之外。

这些环节的利润通常来自电力接入、交付速度、系统集成和可靠性。它们也承担==blue|**更长的建设周期与更重的资本投入**==。机房建成以后，折旧、维护和电力合同仍会继续发生。收入可以随着建设订单快速增长，资本回报则取决于设备是否按期上架、利用率能否达到假设，以及合同能否覆盖资产回收周期。

**调度软件与云平台**

云厂商掌握客户入口、模型部署、任务路由和计费。调度软件可以提高批处理效率，复用缓存，减少空闲和失败重试，让同样的硬件完成更多任务。云平台还可以在 GPU 与自研 ASIC 之间分配工作负载，把硬件成本变化转成客户价格或平台毛利。

这部分利润依赖客户使用规模、软件兼容性和迁移成本，也会受到价格竞争与资本开支的制约。云厂商购买了更多设备，只有在任务收入和现金流跟上以后，系统优势才会转成可持续回报。

## 融资让供给建设早于最终收入

AI 基础设施具有很长的采购和建设周期。云厂商根据客户需求规划算力，GPU 云服务商根据合同建设机房，服务器、内存和封装厂商再根据订单扩产。每个环节看到的都是相对靠前的采购信号，最终用户是否会持续付费，往往要等设备上架以后才能验证。

台积电管理层在 2026 年第二季度业绩电话会上提到，客户各自给出的需求都可能是真实的，把所有需求相加以后仍然需要判断。公司还会检查数据中心的建设、地点和机架进度，避免芯片交付以后进入库存。这段表述说明，上游厂商已经意识到订单与最终部署之间存在距离。

但同时，英伟达已经在和金融机构合作，通过包装芯片为一种金融资产去投资于小型初创企业，在自己扩大销量的同时，间接参与前沿科技投资，并建立深度绑定。这些初创公司根据协议以及需求，需要阶段性继续向英伟达购买芯片。又或者 Meta 成立空壳公司参与数据中心的建设，虽然账面上不影响母公司的业绩，但是这种金融包装行为随着后续的行业不稳定或其他层面的波动极有可能造成破坏性的影响。

这两件事指向同一个机制。融资把决策时点往前挪，也把风险挪到了决策者之外。云厂商和 GPU 云服务商买入设备时，资产和折旧记在自己表内，债务与租赁承诺却是刚性的。设备上架以后，无论上面有没有任务在跑，折旧、电力和利息都在发生；它们能提前锁定的只有合同和预付款，能往后拖的只有终端愿不愿意持续付费。

采购订单又沿着同一条链逐层下发。云厂商按合同规划算力，GPU 云服务商按同一批合同建设机房，服务器、内存和封装厂商再根据这些订单扩产。每一层看到的都是上一层给出的确定信号，没有任何一层能看到所有层加总之后的真实使用量。合同把未来几年的调用预期提前折成今天的订单，这些订单叠加起来的总供给就可能超过当下的付费需求。每一层的判断单独看都成立，加总之后却可能超出真实使用量。

种种现象都没有证明泡沫已经发生，但是又无时无刻不揭示着目前的杠杆越加越大。它们说明长期合同和融资可以把未来收入提前转换成今天的服务器、GPU 和机房。只要有效任务持续增长，提前建设可以缩短交付时间，也能提高资产利用率。需求增速、续约率或利用率低于采购假设以后，租赁、折旧、电力和利息仍会继续发生。

==blue|压力不会同时出现在所有指标上，也不会平均分布。即使模型调用总量仍在增长，只要供给增长得更快，最先承压的是价格类信号，包括 GPU 租赁价格、二手设备残值、服务器库存和部分内存价格。利用率和续约率属于经营结果，滞后一步；资产回报要等折旧和利息走完一个周期才显现。上游还可能在终端需求放缓以前继续收到订单，直到某个环节发现新增收入不足以覆盖资本成本，金融放大过程才会反向传导，造成牛鞭效应。==

## 端侧是等待使用行为验证的第二条曲线

汽车助手和家庭控制中枢需要快速响应，弱网时也要完成一部分操作。车内状态、家庭传感器和个人习惯还涉及隐私，本地处理可以减少部分数据上传。端侧适合承担唤醒、感知、简单决策和高频控制，复杂推理与长上下文仍可以交给云端。

^[同时也更加适合未来的端侧智能助手的记忆、持续学习等功能]

本地运行消耗的是用户设备的电力，设备厂商仍要承担前置投入。更高规格的 SoC、内存和存储会增加 BOM，散热、模型适配、安全、OTA 更新和多年售后也需要工程资源。厂商只有在本地推理能够支持更高售价、减少云端调用支出、改善体验，或者满足隐私与离线要求时，才有理由长期承担这些成本。

端侧芯片还要在有限功耗下处理模型更新。低比特计算、更高效的内存架构和端云调度可以缓解限制，能够部署不等于形成稳定需求。汽车和家庭设备的真实使用频率、本地运行占比、硬件增量成本和产品毛利，仍然是这条曲线最重要的验证指标。

端侧一旦进入高频设备，需求会更分散，也更接近用户每天的真实行为。当前公开材料仍不足以证明这一阶段已经到来，所以我会把它保留为第二条曲线，不把产品演示提前写成大规模芯片订单。

## 未来持续观察的信号

云端需求要看付费任务量、任务完成率和单位任务收入。有效 Token 可以帮助比较推理系统，但它要和延迟、质量、失败率一起看。云厂商的资本开支还要转化为 AI 云服务收入、现金流和更高的每兆瓦产出。

供应链要看 HBM 与标准 DRAM 的价格和库存是否分化，先进封装的交付周期是否缩短，GPU 租赁价格和二手残值是否开始下降。供给紧张带来的利润，只有在扩产以后仍能保持良率、认证优势和客户黏性，才更接近耐久优势。

金融结构要看合同期限、债务期限和 GPU 经济寿命能否匹配。客户续约、机房上架进度和利用率，能够判断长期合同是在锁定真实需求，还是把未来需求提前计入了今天的投资。

端侧要看助手的日均使用次数、本地完成比例和设备毛利。汽车与家庭设备开始承担高频任务以后，端侧芯片需求才会从配置竞争转成用户愿意持续使用的产品能力。

如果有效任务和收入能够跟上算力供给，GPU、ASIC、HBM、封装和数据中心仍有扩张空间。利润会更多留在能降低单位任务成本、掌握受限供给或控制客户与调度入口的环节。当租赁价格和残值这类领先信号持续走弱，利用率、续约和资产回报又持续低于采购假设时，即使 Agent 叙事仍然成立，这一轮基础设施投资也需要下调预期。
