# 全站 GA4 与统计查看入口

日期：2026-10-16。用户已确认从 `/stats/` 一键打开 Google 看板，并要求首页、博客及其他页面统一统计。

## 目标与口径

- 所有 HTML 路由使用同一个 GA4 Web 数据流 `G-6S2MZXN5QQ`，归入媒体资源 `525415859`。
- 首页、文章、项目、CV 和中英文页面既支持直接访问，也支持 Next.js 客户端跳转。
- 浏览次数按页面浏览累加；用户与会话由 GA4 识别，不能把各页用户数相加当成全站人数。
- 本地开发与静态预览不发送数据；只有正式主机 `david188888.github.io` 加载 Google 标签。
- `/stats/` 直接打开用户提供的 GA4 看板地址，不把私人报表数据放入静态站点。

## 设计

1. 在唯一的 `src/app/layout.tsx` 中通过 `next/script`、`afterInteractive` 初始化标签。引导脚本先检查主机名和已有标签，再初始化 `dataLayer`、排队 `js` 与 `config`，异步加载 Google 标签。编号及看板地址集中在 `src/config/analytics.ts`。
2. 页面浏览只由 Google 标签负责。不添加第二套手动 `page_view` 或路由监听器，避免与已启用的历史变化自动采集重复。2026-10-16 读取该编号的公开 `gtag/js` 配置，确认 `vtp_enablePageView: true`、`vtp_enableHistoryEvents: true`，以及目标编号对应的 `__ccd_em_page_view.vtp_historyEvents: true`。这些是当前配置证据，后续修改后台仍需重新验证。
3. `/stats/` 与本地化统计页直接显示私人看板链接、全站统计范围、浏览次数/活跃用户/会话的阅读说明。不显示模拟数字，不声称已收到数据。私人数据的权限仍由 Google 账号控制。
4. 原站点作者登录改为可选的折叠区，保留原先的作者工具解锁和退出行为，以免文章批注工具失去入口。它不再挡住 Google 看板链接。
5. README、统计操作文档、相关作者登录说明与变更记录同步更新。

## 验证与边界

- 测试引导脚本在正式主机初始化一次、在本地主机/其他域名不发送数据，且不额外手动上报页面浏览。
- 验证统计页中英文按钮都指向指定媒体资源，并保持作者工具可用。
- 全部 Vitest 与静态构建通过；检查导出的不同路由均包含全局统计组件。
- 本地浏览器检查统计页桌面与窄屏。正式站点部署后，须用浏览器请求和 GA4 实时报告/DebugView 确认首页→博客→其他页面各产生一次 `page_view`。本地通过不能宣称线上采集已生效。
- 普通 HTML 页面在范围内；直接打开 PDF 等静态附件不能执行标签，其下载点击由 Google 已启用的下载事件统计。
- 本次不创建 Looker Studio、不增加后端或报表 API 凭据。用户已同意打开 Google 看板，使用现有 GA4 即可满足该入口。
