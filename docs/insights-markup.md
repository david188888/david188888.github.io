# Insights 正文标记语法

这份文档是 Insights 文章行内标记的**唯一权威定义**。渲染器、Notion→MDX 转换脚本、翻译校验三处都按这里的规则实现，改规则必须同步改三处。

适用范围：仅 Insights 文章页（`/insights/<slug>/` 与 `/[locale]/insights/<slug>/`）。publications、talks、teaching 走另一条渲染路径，不支持这些标记。

---

## 1. 语法总表

| 语法 | 含义 | 渲染结果 |
| --- | --- | --- |
| `==文字==` | 彩色下划线，默认蓝色 | `<span class="mk mk-blue" data-mark="mk-…">文字</span>` |
| `==red\|文字==` | 彩色下划线，指定颜色 | `<span class="mk mk-red" data-mark="mk-…">文字</span>` |
| `^[批注内容]` | 页边批注，单独成行，挂在前一段落上 | `<div class="note-pair"><p>…</p><aside class="side-note" role="note" data-note="note-…">…</aside></div>` |
| `**粗体**` | 行内强调 | `<strong>` |
| `*斜体*` | 行内强调 | `<em>` |
| `~~删除线~~` | 行内强调 | `<s>` |
| `` `代码` `` | 行内代码 | `<code>` |
| `[文字](https://…)` | 外链，新窗口打开 | `<a href="…" rel="noreferrer" target="_blank">` |

颜色白名单（与 Notion 自身调色板一一对应）：`gray` `brown` `orange` `yellow` `green` `blue` `purple` `pink` `red`。

Markdown 行内解析由 markdown-it 完成，所以 `**` 与 `==` 可以互相嵌套：`**带 ==red|下划线== 的加粗**` 和 `==blue|带 **加粗** 的标记==` 都正确。

---

## 2. 代码段优先

反引号里的 `==` 永远是字面量，不会被当成标记：

```text
代码段保护 `==不是标记==` 结束   →   <p>代码段保护 <code>==不是标记==</code> 结束</p>
```

想在正文里显示 `==` 本身，把它放进代码段即可，不要指望转义。

---

## 3. 失败模式（刻意设计成会报错）

标记系统宁可让构建失败，也不静默把标记渲染成可见的标点。

| 输入 | 行为 |
| --- | --- |
| `==没有闭合` | 抛错：`==` 必须成对出现 |
| `==rede\|拼错颜色==` | 抛错：颜色名不在白名单内 |
| `====` | 抛错：标记内容为空 |
| `正文。 ^[]` | 抛错：批注内容为空 |
| 批注前不是段落（位于文首，或紧跟在标题后） | 抛错：批注必须紧跟在它要标注的段落之后 |
| `^[没有收尾` | 抛错：批注块缺少收尾的 `]` |
| `^[#短语\|内容]` | 抛错：暂不支持锚点短语写法 |

## 4. Notion 侧写法与映射

作者在 Notion 里编辑正文，用 Notion 自己的排版手段；转换脚本负责归约到上面的语法。

| Notion 里的操作 | 转换结果 |
| --- | --- |
| 选中文字 → 文字颜色（红/黄/蓝…） | `==red\|文字==` |
| 选中文字 → 背景色 | `==red\|文字==`（颜色取底色名，去掉 `_bg`） |
| 选中文字 → 下划线 | `==blue\|文字==`（默认色） |
| 文字颜色 + 下划线同时使用 | `==red\|文字==` |
| 给某个段落加评论 | 该段落之后插入 `^[评论内容]` |
| ```html 代码块 | 原样保留，不做任何改写 |

**文字颜色与背景色统一归约为"彩色下划线"**，不再区分文字着色与底色高亮。理由：只保留一种视觉家族，避免同一处文字出现两种互相冲突的强调方式。

### 评论的发布规则

- 默认**所有评论都会发布成页边注**，不需要任何前缀。
- **已 resolve 的 discussion 会被跳过**。这是"不想发布某条评论"的唯一手段：在 Notion 里把它标记为已解决，不用删除。
- 评论挂在标题、列表项等非段落块上时会跳过并写进报告，因为页边注只能挂段落。
- 转换报告会列出每条评论的去向，不会静默丢弃。

## 5. 稳定标识与页面上的隐藏/恢复

### 工具默认对所有人关闭

文章页上的批注工具（管理模式 + 本地标注）**默认不渲染**：未登录的访问者在正文上方只会看到一个很淡的锁图标（阅读区右上角），工具栏本身根本不在 HTML 里。

**开启方式（两种，用的是同一套账号密码）：**

1. 文章页右上角的**小锁图标** → 弹出登录框 → 输入用户名密码 → 工具立即出现。
2. 登录 `/stats/` → 之后打开任何文章页直接就有工具。

两种都会在浏览器里写下一个作者标记（`david-homepage:author`，localStorage），所以**每台设备只需登录一次**，之后打开任何文章都有工具，不需要改 URL。

- 登录实现与凭据校验共用 `src/lib/auth/author.ts`，登录文案也直接复用 `pages.stats`。
- 登录对 `/stats/` 本身仍是按标签页会话（`stats-auth` in sessionStorage），只有作者标记是长期的。
- 兜底：任意文章 URL 后加 `?annotate=1` 也能开启，同样写作者标记。
- 关闭：面板里的「关闭批注工具」按钮，或访问 `?annotate=0`。两者都只会清掉作者标记，不影响 `/stats/` 当前标签页的登录状态。
- **已发布的下划线和批注不受这个开关影响**，它们属于文章 HTML，所有读者都看得到。开关只决定谁拿到编辑与隐藏界面。
- 工具关闭时，本地隐藏过的标记也会回到发布默认（全部显示），但隐藏记录不会删掉：重新打开工具后你的选择还在。

这是一个可见性开关，不是安全边界。凭据本来就随客户端 bundle 发布，任何人都能读出来；它挡住的是公众偶然看到作者界面，而不是真正的保密。它保护的东西也确实不需要保密：`/stats/` 展示的是作者自己也能从别处看到的流量数据，而批注工具只能改动观看者自己的浏览器。

### 稳定标识

每个已发布标记都带一个**内容哈希**生成的稳定 id（`mk-<hash>-<序号>` / `note-<hash>-<序号>`）。

- 哈希取自标记的原始内容，所以**在文章里插入或重排段落不会让 id 漂移**。
- 被标注的文字本身改动后 id 会变，本地隐藏记录自然失效并回到"显示"——这是安全方向，因为读者隐藏的那个标记已经不存在了。
- 同一段内容出现多次时用序号区分（`-1`、`-2`）。

文章页上的「批注」按钮打开管理模式后（需先按上一节激活）：

- 点击已发布的批注或下划线即可隐藏，文字回到没有标注的样子；再点一次恢复。
- 已隐藏的条目在侧栏「已隐藏的标记」里列出，可逐条恢复或「全部还原」。
- 也可以直接选中正文文字，划线或写自己的标注；删除后文字回到纯净状态。
- **全部状态只存在浏览器本地**（`localStorage`，按 slug + 语言分键），不上传、不回写 Notion、不影响其他读者。

## 7. 暂不支持

- 批注锚定到具体短语（`^[#短语|内容]`）。当前页边注只挂段落级别。
- 荧光笔底色块语法（`==` 目前的视觉是下划线 + 淡底色，不提供独立的纯底色高亮）。
- 批注编号、交叉引用、批注折叠。
- 非 Insights 内容页的标记支持。
